Sediakan QCSC-Prefect pada kluster Slurm

Panduan ini menyediakan nod log masuk kluster Slurm sebagai hos aliran kerja qcsc-prefect. Tutorial SQD qcsc-prefect bermula daripada hasil panduan ini.

Selepas anda melengkapkan panduan ini, anda mempunyai item berikut:

ItemLokasiKandungan
~/venv/qcsc-hostNod log masuk, hos aliran kerjaPrefect, pakej qcsc-prefect, dan arahan qcsc-qrmi
~/venv/qcsc-nodeNod pengiraan, dalam job SlurmPekerja QRMI: QRMI dengan arahan task_runnernya, dan qcsc-prefect-qiskit
qrmi-runtimePrefectBlok yang menamakan instans IBM Quantum® dan QPU anda
qrmi_config.jsonNod log masuk dan nod pengiraanKunci API IBM Cloud®, instans dan backend anda untuk QRMI

Jalankan setiap arahan dalam terminal pada nod log masuk, kecuali langkah itu menyatakan sebaliknya.

Prasyarat​

  • Kluster Slurm dengan OpenMPI, PMIx dan pemalam QRMI SPANK, yang dipasang oleh pentadbir kluster. Panduan berikut menerangkan komponen ini:

    • Quantum resource management interface (QRMI)

    • Pemalam SPANK untuk QRMI

    • Panduan pengguna pemalam SPANK

  • Direktori utama dan direktori kerja yang dilihat oleh nod log masuk dan nod pengiraan pada laluan mutlak yang sama

  • Akses HTTPS keluar ke GitHub, PyPI, IBM Quantum dan Prefect Cloud dari nod log masuk, dan ke IBM Quantum dari nod pengiraan

  • Akaun IBM Quantum Platform dengan kunci API IBM Cloud dan sekurang-kurangnya satu instans

  • Akaun Prefect Cloud, atau pelayan Prefect yang anda hoskan sendiri

  • Git, pengkompil C dan C++, CMake, BLAS, LAPACK dan MPI pada kluster, untuk binaan solver dalam tutorial

nota

Contoh menggunakan partition Slurm normal dan nod pengiraan c1 dan c2. Gantikan nama ini dengan nama kluster anda.

Langkah 1: Log masuk ke nod log masuk​

# Run in a terminal on your computer.
ssh <user>@<login-node>

Langkah 2: Pasang uv​

Pasang pengurus pakej uv, dan semak pemasangan:

curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"
uv --version

Langkah 3: Tetapkan laluan dan cipta direktori kerja​

Panduan ini dan tutorial menggunakan dua pemboleh ubah persekitaran:

Pemboleh ubahContohTujuan
QCSC_PREFECT$HOME/qcsc-prefectCheckout qcsc-prefect
QCSC_WORK_DIR/shared/work/qcsc-prefectDirektori kerja bagi job solver dan job QRMI

Kedua-dua laluan mesti berada pada storan yang dilihat oleh nod pengiraan pada laluan mutlak yang sama. Jika kluster anda tidak mempunyai direktori /shared, pilih laluan kongsi yang lain.

Tetapkan pemboleh ubah, dan cipta direktori kerja. Tetapkan semula pemboleh ubah dalam setiap shell baharu sebelum anda mengikuti tutorial:

export QCSC_PREFECT="$HOME/qcsc-prefect"
export QCSC_WORK_DIR=/shared/work/qcsc-prefect
mkdir -p "$QCSC_WORK_DIR"

Untuk menetapkan pemboleh ubah dalam setiap shell baharu secara automatik, tambahkannya pada ~/.bashrc:

# Optional
echo "export QCSC_PREFECT=$QCSC_PREFECT" >> ~/.bashrc
echo "export QCSC_WORK_DIR=$QCSC_WORK_DIR" >> ~/.bashrc

Langkah 4: Klon qcsc-prefect​

Klon repositori, dan checkout tag keluaran, contohnya v0.3.1:

git clone https://github.com/qiskit-community/qcsc-prefect.git "$QCSC_PREFECT"
cd "$QCSC_PREFECT"
git checkout v0.3.1

Langkah 5: Cipta persekitaran aliran kerja​

Cipta persekitaran aliran kerja dengan Python 3.12, dan aktifkannya:

uv venv ~/venv/qcsc-host -p 3.12
source ~/venv/qcsc-host/bin/activate

Pasang pakej qcsc-prefect. Pilihan --no-deps mengekalkan pin versi yang tepat antara pakej checkout. Tutorial memasang aliran kerja itu sendiri:

cd "$QCSC_PREFECT"
uv pip install --no-deps \
  -e packages/qcsc-prefect-core -e packages/qcsc-prefect-adapters \
  -e packages/qcsc-prefect-blocks -e packages/qcsc-prefect-executor \
  -e 'packages/qcsc-prefect-qiskit[slurm]'

Semak bahawa arahan tersedia:

which prefect qcsc-qrmi

Aktifkan ~/venv/qcsc-host dalam setiap shell baharu pada nod log masuk.

Langkah 6: Log masuk ke Prefect​

Log masuk ke Prefect Cloud. Pilih Paste an API key, tampal kunci API Prefect Cloud, dan pilih ruang kerja anda:

prefect cloud login

Semak sambungan. Output menunjukkan PREFECT_API_URL dan ruang kerja anda:

prefect config view
Pilihan: gunakan pelayan Prefect anda sendiri

Langkau nota ini jika anda menggunakan Prefect Cloud. Untuk menggunakan pelayan Prefect anda sendiri dan bukannya Prefect Cloud, ikuti How to run and access a Prefect server on a Slurm login node, dan tetapkan alamat pelayan anda sebagai ganti <server-host>:

# Optional: only for your own Prefect server
prefect config set PREFECT_API_URL=http://<server-host>:4200/api

Langkah 7: Simpan kelayakan IBM Quantum​

Jalankan qcsc-qrmi login selepas log masuk Prefect, kerana ia menyimpan blok qrmi-runtime:

qcsc-qrmi login

Jawab gesaan berikut:

  1. Tampal kunci API IBM Cloud anda. Kunci tidak dipaparkan.

  2. Tekan Enter untuk menggunakan semua instance.

  3. Masukkan nombor instance lalai, 1 dalam contoh berikut.

  4. Masukkan nombor atau nama Backend lalai, 4 (ibm_kingston) dalam contoh berikut.

# Output, with your answers after the prompts
IBM Cloud API key:

Perintah ini juga mencetak nota tentang nod pengiraan dan baris [qrmi] untuk sqd_blocks.toml, yang tidak dimasukkan dalam contoh (...). Anda tidak memerlukan baris [qrmi], kerana aliran kerja membaca instance dan Backend daripada blok qrmi-runtime.

Perintah qcsc-qrmi mempunyai subperintah berikut:

PerintahTujuan
qcsc-qrmi loginSimpan kunci API, instance, dan Backend, serta simpan blok
qcsc-qrmi refreshCari semula instance dan Backend dengan kunci yang disimpan
qcsc-qrmi listCetak instance dan Backend, tanpa kunci
qcsc-qrmi checkSemak bahawa instance blok boleh menggunakan Backend-nya

Pasang fail pada nod pengiraan​

Pemalam SPANK membaca qrmi_config.json pada setiap nod pengiraan, daripada laluan dalam plugstack.conf, selalunya /etc/slurm/qrmi_config.json. Minta pentadbir kluster anda memasang ~/.qiskit/qrmi_config.json anda pada laluan itu. Pasang semula selepas setiap qcsc-qrmi login atau qcsc-qrmi refresh.

Kekalkan Session Mode bagi blok qrmi-runtime pada batch, kerana pemalam SPANK memperoleh QPU dalam batch mode.

Langkah 8: Cipta persekitaran nod pengiraan​

Pekerja QRMI berjalan pada nod pengiraan, dalam persekitarannya sendiri. Cipta daripada checkout yang sama. Pilihan --python mengekalkan ~/venv/qcsc-host aktif:

cd "$QCSC_PREFECT"
uv venv ~/venv/qcsc-node -p 3.12
uv pip install --python ~/venv/qcsc-node/bin/python "qrmi[ibm]"
uv pip install --python ~/venv/qcsc-node/bin/python -e packages/qcsc-prefect-qiskit

Pakej qrmi[ibm] menyediakan perintah task_runner. Tutorial ini menambah cangkuk penyusunan SQD pada persekitaran ini, dan menggunakan ~/venv/qcsc-node/bin/python sebagai python_executable bagi sqd_blocks.toml.

Semak instance dan Backend yang disimpan. Perintah ini tidak pernah mencetak kunci:

qcsc-qrmi list
# Output
API key: set

qcsc-qrmi check
# Output
premium-instance (premium, us-east) can use ibm_kingston.

Semak bahawa Slurm menjalankan tugas pada kedua-dua nod pengiraan, juga dengan PMIx:

srun -N2 hostname
srun -N2 --mpi=pmix hostname
# Output of each command
c1
c2

Semak persekitaran nod pengiraan dan direktori kerja pada nod pengiraan. Perintah pertama tidak mencetak apa-apa apabila import berjaya:

srun -N1 ~/venv/qcsc-node/bin/python -c "import qrmi, qcsc_prefect.integrations.qiskit.qrmi.worker"
srun -N1 ls ~/venv/qcsc-node/bin/task_runner
srun -N1 ls -ld "$QCSC_WORK_DIR"
